# Emoji 反查：词条存在不等于单独输入可达

2026-10-28 对当前工作树的第一次全量审计，固定 Unicode 16.0 的 1,906 个基础 Emoji。在源码仓库中复现（运行时 ZIP 不包含 Python 源码）：

```sh
PYTHONPATH=src python3 -m shi_emoji.reverse_audit --max-reachable 0 --limit 50
```

脚本从固定来源与当前规则在内存中重建反向词条，再逐个把完整词条输入 Python 匹配器，检查目标 Emoji 是否进入前六候选。繁体自动别名与肤色变体不重复计数；不会写入词库或下载数据。`--max-reachable 1` 可看只有零至一个可达词条的项目。这里的“可达”只指匹配器层的孤立词查询，不能推断拼音方案里该候选是否容易选到、最终 Lua 组合是否显示它，更不能当作语义准确率。

| 口径 | 数量 |
|---|---:|
| 基础 Emoji | 1,906 |
| 完全没有词法入口 | 0 |
| 词法入口少于三个 | 444 |
| 孤立词查询中零个入口可达 | 44 |
| 孤立词查询中少于三个入口可达 | 1,049 |

44 个零可达项目的已映射词条全部受到当前 `min_context_len` 门槛限制。这说明原来的反向覆盖统计高估了“直接查一个词就能找到”的体验；不表示这些 Emoji 在长句中也不可达。零可达按大类分布：旅行与地点 11、物品 9、表情与情绪 6、活动 6、动物与自然 5、人物与身体 4、食物与饮品 3。

第一批值得人工审定的是对象明确、日常会独立输入的名称，例如 `鸭子→🦆`、`蜘蛛→🕷️`、`蘑菇→🍄`、`培根→🥓`、`气球→🎈`、`沙漏→⌛`、`图钉→📌`、`椅子→🪑`。这些现有词条都被长度门槛挡住；其中一些还需要先纠正首选顺序，例如“培根”当前词法候选把 🐖 排在 🥓 前，“气球”把 💬 排在 🎈 前，“椅子”把 💺 排在 🪑 前。不能只撤掉门槛而不复核排序。

另一批需要语境或命名判断，例如 `花痴→😍`、`迷茫→😶‍🌫️`、`累死了→😩`、`船→🚢`、`雪人→⛄`。有的单字太宽，有的与已人工定义的组合表达竞争；直接批量解锁会重新引入误联想。后续应逐词标记“本义／正式名称／联想”、允许独立触发与否，并对照未参与补词的样本评估误报。此页是待审清单，不是已修复声明。

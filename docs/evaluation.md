# 测试能证明什么

## 工程与回归检查

本机完整套件包括数据和导出一致性、逐词合并不串词、组合范围、词边界、Python/Lua 一致性、偏好、原生菜单记忆、候选提交、ZIP 隔离生命周期及文档检查。它们证明对应机制与已知例子没有回归，不证明任意中文的语义正确率。发布候选版本的实测数量记录在发布工程说明中，不把不断变化的测试数当成产品质量指标。

主库的反向词法覆盖报告采用固定 Unicode 16.0 分母。1,906 个基础 Emoji 有映射入口，不等于在任意句子里可达；最终后缀还受边界、概念选择、肤色/性别等影响。统计口径改变必须保留变化原因，不靠放宽预算伪造改善。

短词策略改为看当前高亮的完整中文候选，而不是删除双字模型词条：孤立的 1～2 字候选只接受人工规则、明确本义和唯一的正式名称；较弱的双字联想需候选至少 5 字。单字仅保留 `data/short_term_policy.json` 中逐字审定的直接映射和少量长句线索。例：“冰”可联想 🧊，“病／好／好人”独立候选不联想；“你真是一个好人”可联想 🫵 🦸。用户输入尚未形成完整候选时，插件本来也不会处理局部词。

这项降噪与明确映射校正后，不足 3 个入口的基础 Emoji 为 444，不足 4 个为 652；覆盖预算按真实映射重定基线，不把覆盖变化解释为语义质量提升。“月亮”不再错误地贡献给上弦月、下弦月和盈凸月，使后一个计数比原短词草稿增加 3。零入口仍为 0。新规则是否减少真实输入时的误联想，仍需独立样本验证。

## 语义验收尚未完成

开发者见过并用于补词的例子只属于回归集。不能用自己的调试例子报告泛化准确率，也不能把模型相似度当概率。

独立评测流程应先冻结版本，再从未用于建库的独立来源抽样；允许多个合理表情，也允许“不加表情最好”。同时统计误联想、漏联想、错误中文解释和对原候选的干扰。一旦样本被用于调词，下版就不能继续称其为盲测。

真实试用不要求用户按测试题输入。默认不收集文字、用户词库或后台日志；需要用户自愿提交已脱敏例子。当前没有独立整体准确率。

## 性能结论的边界

Lua matcher 微基准、宿主整段按键模拟、目标应用 UI 延迟是三个指标，不能互相替代。历史毫秒数据只适用于当时版本及环境。当前尚无跨机器、长期运行的内存/延迟验收，不宣称零开销或实时模型级理解。

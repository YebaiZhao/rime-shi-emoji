# 逐词合并与来源追溯

本节记录的是当时逐词合并阶段；其中“未部署”只描述该阶段，不代表当前运行时状态。

## 查明的问题

旧模型产物 `data/model_phrases.json` 中，“奶牛”已经包含 `🐂🍺`，不是本轮合并才生成的错误。旧合并代码同时存在另一个机制问题：多个短语共享同一个规则对象，给一个词追加 emoji 会改变整组短语。

原模型产物及其审核摘要保持原样，保留历史证据；编译阶段执行明确的隔离和优先级策略，不把修改过的产物冒充原审核结果。

## 当前策略

- 按词深拷贝规则，每个词的输出独立；语义分组 ID 可保留，用于句子中去重，但不再共享可变映射列表。
- 明确监督表达优先（300）；CLDR 正式名称、国旗名称派生入口、人工本义及人工关联其次（200）；历史模型产物再次（100）；CLDR 普通关键词最后（50）。关键词不一定是同义词，不能仅因来自 CLDR 就压过已有映射。
- 每个词采用最高级来源的完整映射，不再盲目合并所有来源的表情列表。来源内部顺序保留。
- 带显式 `suffix` 的指定组合，例如 `🐂🍺`，不允许历史模型映射扩散到授权词之外；人工监督规则自己的显式映射保留。此限制不等于已审核全部模型联想。
- 原始及可用 emoji、来源、类别、是否采用写入开发侧 `mapping_audit`。这些诊断信息不打入输入法运行时。

人工本义位于 `data/literal_aliases.json`；人工联想仍在 `data/lexical_aliases.json`；二者不混称模型结果。本轮仅整理牛类入口及“亲亲脸”（其正式名称“亲亲”已有人工监督映射，独立入口避免覆盖用户语义选择），尚未逐类整理动物、食物等全部俗称。

## 查询原因

```sh
PYTHONPATH=src python -m shi_emoji.match 奶牛 --top-k 20
```

返回 `mapping_sources`：能看到模型原来给了什么、哪些表情被范围规则排除、最终采用哪个来源。运行时 ZIP 仍只包含匹配所需字段。

## 当前输出与验收边界

Lua 最终增强后缀已检查：牛/老牛→🐄 🐂，黄牛→🐂 🐄，奶牛→🐄 🐮，牛逼→🐂🍺。牛类本义映射可有三个候选表情，但当前单意图后缀最多展示两个，未改变交互上限。

按新决策策略，仍有 1,906 个基础 emoji 均有词法入口；不足三入口从 362 变为 405，不足四入口从 551 变为 601，没有首选入口从 11 变为 12。这是删除来源混合带来的真实映射减少，不是质量提升证明。新旧统计和预算调整原因保存在 `data/merge_policy_baseline.json`；不能用旧覆盖数字宣称新版本更好。

本轮测试验证输入不变性、逐词隔离、确定性、组合范围和已知回归，不证明未知表达的语义正确率。黄牛仍可能表示倒票者；本轮未做语境消歧。

严格本地发布检查 68 项通过、无跳过，含原生 Rime 与 ZIP 隔离生命周期。动物、食物、交通等全部类别的日常名称整理仍未完成；本轮是先修生产线及牛类样例，不声称已完成系统扩词。

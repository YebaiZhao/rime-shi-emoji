# 实验功能：0 键上屏 Emoji

开发版的备用键为 `⌥+0`（Rime 事件名 `Alt+0`）；alpha.3 发布包仍使用 `Shift+0`。开发版已通过 Lua 按键测试，真实 macOS 键盘布局上的表现仍需验证。

在当前高亮的完整中文候选有主库联想时，主键区 `0` 执行选单所选的上屏方式，`⌥+0` 执行另一种。默认选中「原文＋Emoji」：`0` 上屏 `虾仁 🦐 🍤`，`⌥+0` 上屏 `🦐 🍤`；切到「仅Emoji」后，两键对调。候选旁只显示简短的 `〔0→🦐 🍤〕`，不重复显示原文，也不标注 `⌥+0`；完整上屏内容由选单状态决定。空格和 1～6 仍选原文；没有联想、诗Emoji关闭或英文模式时，两键交还原输入方案处理。

在已有中文方案的 `*.custom.yaml` 的 `patch` 下加入：

```yaml
  "menu/page_size": 6
  "shi_emoji/candidate_slot": false
  "shi_emoji/zero_key": true
```

在同一方案补丁的**现有** `switches/+` 列表末尾追加以下一项，不要新建第二个 `switches/+` 键：

```yaml
    - name: shi_emoji_emoji_only
      states: [原文＋Emoji, 仅Emoji]
```

在 `default.custom.yaml` 的**现有** `switcher/save_options/+` 列表追加 `shi_emoji_emoji_only`，与 `shi_emoji` 总开关一起保存。不要给此开关加 `reset`；未保存过时默认「原文＋Emoji」，之后记住各账号在选单中的选择。

重新部署并重载后，选单会多一项输出方式。选单文字显示**当前状态**：初次看到「原文＋Emoji」，点它才切到「仅Emoji」；再点「仅Emoji」切回来。该模式不新增候选行；高亮换到同音词时，两键的内容也跟着换。万象的 `7` 恢复原用途，但高亮词有 Emoji 时，`0` 和 `⌥+0` 会接管原方案的按键功能；没有 Emoji 时仍按万象原规则处理。⌥+回车在这个实验中暂作兼容键，与 `⌥+0` 同效；未启用实验的方案仍按原方式提交「原文 + Emoji」。⌃⌥+回车的重口联想行为不变。插件不再接管 `Shift+0`，不修改原方案的 Shift 中英切换配置。

## 下一轮集成验证待办

- 两种输出菜单状态下，验证 `0` 与 `⌥+0` 对调；保留简短预览和原候选顺序。
- 在真实 macOS 键盘布局下确认 Option+0 的事件编码，包含 Option 按下、0 按下／松开、Option 松开的完整序列；检查上屏后中英状态不变、无多余字符，并覆盖左右 Option。当前实现识别带 Alt 修饰的 `0`，特殊字符事件的适配待实际确认。
- 检查 `Shift+0`、右括号和单按 Shift 不被插件接管，保留原方案行为。
- 覆盖无联想、插件关闭、英文模式及实验关闭的透传，以及额外 Ctrl／Shift／Super 修饰键不误触。
- 检查 ⌥+回车兼容路径与 ⌃⌥+回车重口路径未受影响，执行更新后的自动化用例及隔离原生验证。

不要与[第 7 项候选槽实验](experimental-candidate-slot.md)同时启用。关闭此实验时，删除 `shi_emoji/zero_key`、对应的 `shi_emoji_emoji_only` 选单项及保存项，并按原方案需要恢复页面大小，重新部署。

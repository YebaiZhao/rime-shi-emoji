# 完整词保护与正反例评测

## 句中范围审定接入

运行数据从 `data/sentence_scope_review/` 的七批审定记录逐条生成。2,590 条新增句中线索需通过两端词边界和语境检查。548 条继续仅匹配完整候选，2,250 条待消歧关系也维持完整候选范围。档位和重口开关照常生效。

句中边界按固定 Jieba 词频计算，并检查接近最优的切分是否跨越线索任一端。简繁词形均由构建时数据提供。标点可提供明确边界，连续的英文字母或数字内部不产生边界。保护词仍参与检查，常见否定、引号和转述会阻止新增线索触发。该方法依赖词典和表面语境，缺词和多义切分仍可能导致误判。

实际 Lua 回归逐条核对 5,388 条关系的完整候选、最低档位和句中许可，另用独立文本验证词内片段、跨词拼接、简繁、混合字符及语境。词频表可用 `python -m shi_emoji.boundaries` 从固定 Jieba 数据和 OpenCC 重新生成。

## 严格与一般档验收

第三阶段覆盖核心审定、运行词表及完整候选补充表合并后的全部 13,257 个不同表达。两档共执行 26,514 次 Lua 查询，核对原始关系、实际后缀、整词优先级、固定组合与显示名额。1,906 个基础 Emoji 在每档均有至少一个符合过滤器资格、可显示的中文完整候选入口。

严格档补缺为 64 个 Emoji 核定了完整候选名称。相关审定及简繁形式写入 `data/strict_entry_reviews.json`，沿用完整候选补充表，句中权限沿用原审定。可用 `python scripts/check_stage_three.py --output /tmp/shi-emoji-stage3.jsonl.gz` 重跑全量验收。隔离万象另对新增或补强的 67 个名称验证两档候选、预览及两种提交方式，其中 28 个依赖可选拼音补充。

在本机 arm64 的 Squirrel Lua 上，对固定 12 个输入轮流运行严格与一般档共 2,400 次。与改动前 HEAD 比较，热查询 p95 从 0.021 ms 到 0.048 ms，Lua 回收后内存从 31.6 MiB 到 37.7 MiB。首次需要新词边界表的句子用时约 20 ms。测量范围为 Lua 过滤器 CPU 时间，不含宿主组句或界面延迟。

## 原理

构建时从固定版本 jieba 名词词典筛选：词频至少 3、3–8 个汉字，且内部含有已映射的较短短语。当前编译 20,149 个保护词。不是为“电动车”“开发票”逐一写例外，也不在运行时加载 jieba、Python 或模型。

运行时先用构建时压平的保护词 trie 找到保护词跨度，不在输入进程里为每个保护词前缀建立 Lua 表。若 emoji 短语严格包含在某个保护词内部，就不把它当独立意图；与保护词完全相等的匹配、覆盖保护词的更长匹配仍然允许。Python 和 Lua 使用同一保护词规则；中文长句依然逐位置检索。

- `电动车`：完整词可出 `🛵 🔋`，内部“动车”不会出 `🚄 🚅`。
- `今天坐动车回家`：“动车”仍可命中。
- `开发`、`开发软件`、`程序开发`：人工监督关联 `🧑‍💻`。
- `开发票`：内部“开发”不会触发程序员。
- `中午去吃火锅`：仍命中火锅。构建不采用 jieba 的 `l`（习用语）类，避免将“吃火锅”当不可拆名词。

`电动车→🛵 🔋` 为日常两轮电动车的近似表达，不代表存在专用电动车 Unicode 符号；“开发”默认编程联想也不是通用词义判断。这些人工关联保存在 `data/lexical_aliases.json`，没有冒充模型推断。

## 构建与测试

```sh
PYTHONPATH=src python -m shi_emoji.coverage --fetch --check
PYTHONPATH=src python -m shi_emoji.wordguards
PYTHONPATH=src python -m shi_emoji.tier_export
PYTHONPATH=src python -m unittest discover -s tests -v
```

还需要已缓存的固定 jieba 数据；其下载步骤在 `python -m shi_emoji.sources`，来源、许可和 SHA-256 见 `data/source_manifest.json`。保护词产物 `data/word_guards.json` 也记录来源摘要；再分发保留 jieba MIT 声明。

评测集 `data/matching_cases.json` 有 16 条正反例，检查应有及禁有表情；Lua 对这些例子逐项与 Python 结果比较。真实隔离 Rime 引擎另测“开发”“电动车”“开发票”的最终候选行为。共 59 项测试通过，不等于开放文本总体准确率。

本机 Lua CPU 微基准：六种短词/长句轮询 1,200 次，双 trie 建立约 38.95 ms，热查询 p50 0.038 ms、p95 0.058 ms。仅测索引建立与 matcher 查询，不含 Lua 文件加载、拼音翻译、GUI 或进程启动；不是端到端输入延迟。开发运行时 ZIP 为 205,111 字节。

## 限制

这不是完整分词，也不是语义理解。保护词典缺词时仍可能误拆；复合词可能被过度保护，例如“花生油”不再从内部“花生”产生联想。词典本身含专名及低频词，尚无大规模盲测结果。`房地产开发` 的“开发”仍可能错误联想到程序员，需要后续上下文消歧，而不是靠词边界承诺解决。

下一步应扩大独立正反例集，分别统计误报、漏报、最终增强候选可达性和运行时性能，不以词库数量代替质量验收。

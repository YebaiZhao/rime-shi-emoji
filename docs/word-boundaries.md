# 完整词保护与正反例评测

> 历史阶段记录：微基准、体积、覆盖和测试数对应当时版本，不代表当前发布版。主线概况见 [架构](architecture.md)，实际可再现的工程检查见 [发布工程](release-engineering.md)。

本轮仅开发和隔离验证，没有更新已安装输入法。

## 原理

构建时从固定版本 jieba 名词词典筛选：词频至少 3、3–8 个汉字，且内部含有已映射的较短短语。当前编译 20,149 个保护词。不是为“电动车”“开发票”逐一写例外，也不在运行时加载 jieba、Python 或模型。

运行时先用第二棵轻量 trie 找到保护词跨度。若 emoji 短语严格包含在某个保护词内部，就不把它当独立意图；与保护词完全相等的匹配、覆盖保护词的更长匹配仍然允许。Python 和 Lua 使用同一规则；中文长句依然逐位置检索。

- `电动车`：完整词可出 `🛵 🔋`，内部“动车”不会出 `🚄 🚅`。
- `今天坐动车回家`：“动车”仍可命中。
- `开发`、`开发软件`、`程序开发`：人工监督关联 `🧑‍💻`。
- `开发票`：内部“开发”不会触发程序员。
- `中午去吃火锅`：仍命中火锅。构建不采用 jieba 的 `l`（习用语）类，避免将“吃火锅”当不可拆名词。

`电动车→🛵 🔋` 为日常两轮电动车的近似表达，不代表存在专用电动车 Unicode 符号；“开发”默认编程联想也不是通用词义判断。这些人工关联保存在 `data/lexical_aliases.json`，没有冒充模型推断。

## 构建与测试

```sh
PYTHONPATH=src python -m shi_emoji.coverage --fetch --check
PYTHONPATH=src python -m shi_emoji.wordguards
PYTHONPATH=src python -m shi_emoji.export
PYTHONPATH=src python -m unittest discover -s tests -v
```

还需要已缓存的固定 jieba 数据；其下载步骤在 `python -m shi_emoji.sources`，来源、许可和 SHA-256 见 `data/source_manifest.json`。保护词产物 `data/word_guards.json` 也记录来源摘要；再分发保留 jieba MIT 声明。

评测集 `data/matching_cases.json` 有 16 条正反例，检查应有及禁有表情；Lua 对这些例子逐项与 Python 结果比较。真实隔离 Rime 引擎另测“开发”“电动车”“开发票”的最终候选行为。共 59 项测试通过，不等于开放文本总体准确率。

本机 Lua CPU 微基准：六种短词/长句轮询 1,200 次，双 trie 建立约 38.95 ms，热查询 p50 0.038 ms、p95 0.058 ms。仅测索引建立与 matcher 查询，不含 Lua 文件加载、拼音翻译、GUI 或进程启动；不是端到端输入延迟。开发运行时 ZIP 为 205,111 字节。

## 限制

这不是完整分词，也不是语义理解。保护词典缺词时仍可能误拆；复合词可能被过度保护，例如“花生油”不再从内部“花生”产生联想。词典本身含专名及低频词，尚无大规模盲测结果。`房地产开发` 的“开发”仍可能错误联想到程序员，需要后续上下文消歧，而不是靠词边界承诺解决。

下一步应扩大独立正反例集，分别统计误报、漏报、最终增强候选可达性和运行时性能，不以词库数量代替质量验收。
